# Размещение BUB на российском сервере без VPN

## Почему недостаточно GitHub Pages

GitHub Pages публикует только статические HTML/CSS/JS-файлы. BUB также требует Node.js API для регистрации, входа, поездок, заявок, сообщений и геолокации. На GitHub Pages эти API-маршруты не запускаются. В рабочем варианте Node.js-сервер должен одновременно отдавать папку client и обрабатывать /api.

## Рекомендуемая схема

- Российский VPS/VDS (например, Timeweb Cloud или Beget) — один сервер для сайта и API.
- Node.js 20 + Docker Compose.
- Один origin для страниц и API: браузер открывает сайт и отправляет запросы на тот же домен /api. Это исключает проблему сторонних cookie между GitHub Pages и отдельным API-доменом.
- JSON-база BUB хранится в постоянном Docker volume bub-data, а не в файловой системе контейнера.
- Leaflet подключается локально из npm-пакета, а не с внешнего CDN.

## Деплой на VPS

1. Создайте VPS в дата-центре России (Москва или Санкт-Петербург), установите Ubuntu 22.04/24.04 и Docker Engine + Docker Compose.
2. Подключитесь по SSH и клонируйте репозиторий:
   ```bash
   git clone https://github.com/slava0213/BUB.git
   cd BUB/hitch-a-ride
   ```
3. Создайте секрет:
   ```bash
   cp .env.example .env
   openssl rand -base64 48
   ```
   Вставьте полученную строку в JWT_SECRET в файле .env. Укажите настоящий адрес администратора в SUPPORT_ADMIN_EMAIL.
4. Запустите:
   ```bash
   docker compose up -d --build
   ```
5. Проверьте API на сервере:
   ```bash
   curl http://127.0.0.1:3000/api/health
   ```
   Ожидаемый ответ — JSON с ok:true.
6. Настройте Nginx как reverse proxy на 127.0.0.1:3000, подключите домен и HTTPS-сертификат. Не открывайте порт 3000 в публичный интернет; наружу должны смотреть только 80/443.
7. Откройте домен без VPN и проверьте регистрацию, вход, создание поездки, заявки, чат и геолокацию с мобильного интернета.

## Обновление

```bash
cd BUB
git pull
cd hitch-a-ride
docker compose up -d --build
```

## Резервное копирование

База находится в Docker volume bub-data. Настройте ежедневный backup volume/файла carpool.json на отдельное хранилище. Не удаляйте volume при обновлении контейнера.

## Важные ограничения

- Для дорожной подложки карты, геокодинга и точных автомобильных маршрутов код использует OpenStreetMap, Nominatim и публичный OSRM. Если эти внешние сервисы недоступны, точный маршрут или подложка карты могут не загрузиться; у геомодуля есть приблизительный расчёт как резерв.
- Фотографии автомобилей, для которых используются внешние Wikimedia/CarAPI URL, также остаются внешними. Чтобы убрать эту зависимость полностью, сами файлы фотографий нужно хранить в client/images/cars/ и ссылаться на локальные пути.
- Размещение в российском дата-центре уменьшает зависимость от зарубежного хостинга, но не гарантирует доступность всех внешних API и картографических тайлов.
- Текущая база BUB — JSON-файл, а не PostgreSQL. Для небольшого учебного проекта это проще, но для реального публичного сервиса с несколькими одновременными записями лучше мигрировать на PostgreSQL и настроить автоматические резервные копии.
- GitHub Pages можно оставить как зеркало/демо, но рабочую ссылку для пользователей нужно направить на домен, который обслуживает этот Node.js-сервер.


## Быстрый пробный запуск на Amvera (российские регионы)

В репозитории добавлен корневой `amvera.yaml`: он указывает Dockerfile BUB, порт 3000 и постоянное хранилище `/data`. Amvera не запускает `docker-compose.yml`; для этого способа используется обычный Dockerfile.

1. Зарегистрируйтесь в Amvera и создайте приложение в российском регионе. Для первого теста выберите пробный тариф и проверьте стартовый баланс и текущую стоимость в личном кабинете: пробный ресурс не является бессрочным бесплатным тарифом.
2. Подключите репозиторий GitHub `slava0213/BUB` (ветка `main`) либо перенесите его содержимое в репозиторий Amvera.
3. Убедитесь, что в корне репозитория находятся `amvera.yaml` и папка `hitch-a-ride`.
4. В настройках приложения добавьте секрет `JWT_SECRET` со случайной длинной строкой (например, сгенерированной командой `openssl rand -hex 32`). Не публикуйте этот секрет в GitHub и не отправляйте его в чат.
5. Запустите сборку. После успешного старта откройте выданный Amvera домен и проверьте `/api/health`: должен вернуться JSON с `"ok":true`.
6. Проверьте регистрацию, выход/вход, создание поездки, заявки, сообщения и отслеживание. Делайте тест с российской мобильной сети без VPN.
7. До запуска для реальных пользователей настройте резервную копию данных и проверьте, что файл `/data/carpool.json` сохраняется после перезапуска приложения.

**Хранение:** BUB использует JSON-файл. Для Amvera переменная `DB_PATH` в Dockerfile указывает на `/data/carpool.json`, а `amvera.yaml` монтирует постоянное хранилище в `/data`. Не меняйте этот путь на папку исходного кода.

**Важно:** бесплатный домен и SSL не означают бесплатный вычислительный ресурс. По опубликованным тарифам Amvera пробный контейнер тарифицируется; перед запуском проверьте текущий баланс и тариф. Доступность самого домена, картографических сервисов и геокодинга из конкретной сети РФ нужно проверить отдельно.
