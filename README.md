# 🚗 сервис поиска попутчиков

Веб-приложение: поездки, заявки, живой чат, отзывы и рейтинг водителей.

## 🛠 Стек
- **Frontend:** HTML, CSS, JavaScript (без фреймворков)
- **Backend:** Node.js + Express
- **Авторизация:** JWT (httpOnly cookie) + bcrypt
- **Хранилище:** JSON-файл `server/carpool.json`

## ✏️ Ваши контакты
Откройте `client/js/config.js` и впишите имя, Telegram, e-mail и телефон —
они появятся в бегущей строке и в подвале каждой страницы.

## 🚀 Локальный запуск
```bash
cd server
npm install
npm start
```
Откройте http://localhost:3000

При первом запуске создаются демо-поездки (помечены «демо»).
Отключить: переменная окружения `SEED_DEMO=0`.

## 🌐 Бесплатный хостинг (Render)
В репозитории настроен Blueprint для бесплатного Web Service.
1. Откройте https://render.com и подключите GitHub.
2. Выберите **New → Blueprint** и репозиторий **BUB**.
3. Render прочитает `hitch-a-ride/render.yaml`; сервис запускается командой `npm start`.
4. После деплоя откройте выданный Render URL.

> Бесплатный тариф может переводить сервис в режим ожидания после периода без запросов, поэтому первый запуск после паузы бывает медленным. Локальный JSON-файл на бесплатном Render не является надёжным постоянным хранилищем: данные могут сбрасываться при перезапуске или повторном деплое. Для постоянных поездок, заявок и сообщений подключите PostgreSQL.

> GitHub Pages не подойдёт для полного приложения: здесь нужен Node.js-сервер.

## 🛟 Техническая поддержка BUB

Страница поддержки: `client/support.html` (пункт «Поддержка» в основном меню).
- Пользователь может отправить обращение без входа в аккаунт.
- У каждой заявки есть номер, статус и защищённый персональный ключ для доступа к переписке.
- Зарегистрированные пользователи видят свои заявки в личном списке.
- Ответы администратора и история сообщений хранятся на сервере.
- Статусы: «Новое», «В работе», «Ожидает ответа», «Решено».
- Административная очередь доступна только аккаунту, email которого совпадает с переменной окружения `SUPPORT_ADMIN_EMAIL`.

**Настройка администратора на Render:** откройте Dashboard → сервис BUB → Environment и задайте `SUPPORT_ADMIN_EMAIL` равным email аккаунта, которым вы будете входить в BUB. Переменная также добавлена в Blueprint как несинхронизируемая — её значение нужно указать вручную. Не используйте демо-аккаунты в качестве администратора.

Обращения и сообщения сейчас добавляются в JSON-хранилище `server/carpool.json`. Для постоянной работы на Render подключите PostgreSQL или другое постоянное хранилище: файловая система бесплатного сервиса может очищаться при перезапуске/деплое. Автоматические email-уведомления и прикрепление файлов пока не реализованы.

## Отслеживание поездки (новое)

Страница `track.html?trip=ID` показывает на карте, где сейчас водитель, и считает, когда он приедет.

- Водитель нажимает «Начать поездку» — браузер передаёт геопозицию (нужен HTTPS или localhost).
- Пассажир с **принятой** заявкой видит водителя, время прибытия в пункт назначения и до своей точки посадки (её можно отметить на карте или по геопозиции).
- Время считается через OSRM по дорогам, без пробок. Если сервис недоступен, используется оценка по прямой (помечается как ориентировочная).
- Для показа без выезда есть кнопка «Симуляция» (ускорение ×30 / ×60 / ×120).
- Координаты городов: встроенный справочник, затем Nominatim. Для старых поездок определяются автоматически при первом открытии карты.
- Позиция хранится только в памяти сервера и удаляется при завершении поездки.

API: `POST /api/trips/:id/start | finish | location | pickup`, `GET /api/trips/:id/tracking`.

## Оформление

Страницы по требованиям: Поездки (`index.html`), Создать поездку, Поиск, Чат, Профиль (плюс вход и регистрация).
Дизайн в духе макета такси: баннер, круглое меню, жёлтые карточки слева (быстрый поиск, популярные направления), блок «Автомобили наших водителей» (машины рисуются в `js/cars.js`), центрированное меню в подвале.
Данные временно хранятся в JSON (`server/carpool.json`), позже планируется БД.


## Фотографии автомобилей

Карточки автопарка используют реальные фотографии моделей из Wikimedia Commons через CarAPI (carapi.trustcar.info). Сервис возвращает сведения об авторе и лицензии; подпись к каждому найденному фото выводится под изображением. Если для модели нет фотографии, показывается нейтральная заглушка. Изображения и метаданные загружаются с внешнего сервиса, поэтому для их отображения нужен интернет.
